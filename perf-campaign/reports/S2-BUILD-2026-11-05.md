## How JSRF_GEN_OPT is applied (shipped mechanism)

- `tools/switch/build.sh` passes `-DJSRF_GEN_OPT="${JSRF_GEN_OPT:-}"`
  to CMake on every run (it is never remembered in the cache from an
  earlier build).
- `port/CMakeLists.txt` (the `JSRF_GEN_OPT` cache-string block after
  the "C flags:" status line, ~lines 153–165): the option is for the
  generated code only.
- Application point (~lines 190–205): `JSRF_GEN_SOURCES` is the glob
  of `${JSRF_GEN_DIR}/*.c` plus, conditionally,
  `port/recomp_tables_none.c`. Those files get per-source
  `COMPILE_OPTIONS` = `-ffp-contract=off;-fwrapv;-fno-strict-aliasing`
  (the semantic flags) with `JSRF_GEN_OPT` appended after them, so a
  `-O3` there comes last and wins for those files.
  `recomp_manual.c` only gets a `JSRF_GEN_OPT_DESC` define so the run
  log can state the flags.
- Everything else in the build inherits the toolchain/Release flags.

## The S2 change (copy only, `~/jsrf-nx-s2/port/CMakeLists.txt`, +27 lines, insertions only, no source logic touched)

Mechanism chosen: `target_compile_options(<target> PRIVATE -O3)`
applied AFTER each target is defined, so the -O3 lands after both
the Release -O2 and each library's own explicit -O2 (GCC honours the
last -O). A global `CMAKE_C_FLAGS_RELEASE` override would NOT have
worked: the libraries' own trailing `-O2` would still have won.

```diff
@@ after add_subdirectory("${JSRF_REPO}" "${CMAKE_BINARY_DIR}/xboxrecomp")
+# S2 VARIANT (runtime at -O3, local experiment, not upstream): every
+# runtime library target gets -O3 appended AFTER its own compile options,
+# so it overrides the -O2 those targets (and the Release config) carry.
+# The generated game code is not touched by this block: it lives in the
+# jsrf_recomp executable and keeps its per-source options (semantic flags,
+# then JSRF_GEN_OPT) exactly as before. INTERFACE libraries have no
+# objects to optimise and are skipped. Prebuilt devkitPro portlibs
+# (SDL2, libnx, Mesa) are not rebuilt by this project at any opt level.
+foreach(_jsrf_s2_target platform uam xbox_nv2a_dk xbox_kernel xbox_d3d8
+        xbox_dsound xbox_apu xbox_nv2a xbox_usb xbox_input xbox_video
+        xbox_nv2a_gl xbox_menu)
+    if(TARGET ${_jsrf_s2_target})
+        get_target_property(_jsrf_s2_type ${_jsrf_s2_target} TYPE)
+        if(NOT _jsrf_s2_type STREQUAL "INTERFACE_LIBRARY")
+            target_compile_options(${_jsrf_s2_target} PRIVATE -O3)
+            message(STATUS "S2: runtime target ${_jsrf_s2_target} at -O3")
+        endif()
+    endif()
+endforeach()
+
@@ before target_compile_definitions(jsrf_recomp PRIVATE JSRF_VERSION=...)
+# S2 VARIANT: the executable's own (non-generated) sources -- main.c,
+# recomp_manual.c, resource_load.c, xbe_check.c, ios/xiso.c, the Switch
+# glue and the generated shader_seed.c -- compile at -O3 too. Target
+# options precede per-source options, so the generated sources' own
+# -O3 (via JSRF_GEN_OPT, appended after their semantic flags) still
+# comes last for them, exactly as in the shipped build.
+target_compile_options(jsrf_recomp PRIVATE -O3)
```

Configure output confirmed all ten real targets:
`S2: runtime target platform / uam / xbox_nv2a_dk / xbox_kernel /
xbox_dsound / xbox_apu / xbox_nv2a / xbox_usb / xbox_input /
xbox_video at -O3` (xbox_d3d8 skipped as INTERFACE; xbox_nv2a_gl and

## Risk notes

- **Not a null build** (see Verdict). The one part of "runtime" S2
  cannot reach is the prebuilt portlibs (SDL2/libnx/deko3d/Mesa
  binaries from devkitPro) — they are linked, not compiled, in both
  builds.
- **-O3 miscompile risk is the thing being tested, not a desk
  finding:** the runtime was only ever validated at -O2 upstream.
  The kernel/NV2A emulation code is aliasing- and overflow-sensitive
  in places (the generated code carries `-fwrapv` /
  `-fno-strict-aliasing` for exactly that reason; the runtime does
  not, in either build). If S2 misbehaves on hardware (visual
  corruption, hangs, crashes where baseline is clean), that is a
  plausible -O3-exposed UB signature, not necessarily a campaign
  error — worth one re-check run before drawing frame-time
  conclusions either way. Desk-side, the build produced no new
  warning classes beyond the shipped build's own.
- **Boot smoke is still owed:** per the LOQ storage-rollback history,
  an LOQ build is not fully trusted until it boots. The hash chain
  above rules out file-level rollback for the staged copy, but the
  first S2 console run doubles as its boot proof — the coordinator
  should treat a failure to boot as "S2 build suspect", swap the
  shipped NRO back (procedure step 3), and report it rather than
  debugging on the campaign clock.
- The copied tree `~/jsrf-nx-s2` and `~/jsrf-switch-build-s2` remain
  on the LOQ for reproducibility (the diff above plus
  `-DJSRF_VERSION=0.4.0-switch` in the build cache are the whole
  recipe). The original tree `~/jsrf-nx` is untouched.
- No console contact was made; the console's resident NRO, options
  and claim state are exactly as this worker found them (unprobed).
